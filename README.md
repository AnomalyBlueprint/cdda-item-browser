# CDDA Item & Sprite Browser

[![Live Demo](https://img.shields.io/badge/Live_Site-Launch_App-success?style=for-the-badge)](https://anomalyblueprint.github.io/cdda-item-browser/)

A blazing fast, lightweight, browser-based tool for tracking tileset and sprite completion in [Cataclysm: Dark Days Ahead (CDDA)](https://github.com/CleverRaven/Cataclysm-DDA).

## What is this?
This tool dynamically extracts metadata and sprite canvas renders across all 11 official CDDA tilesets and compiles them into highly optimized JSON files. It allows developers and artists to quickly search for items, terrains, and monsters, instantly verifying which tilesets are missing sprites for a specific entity.

### Features
- **Instant Search:** Find entities instantly through optimized indexing.
- **PWA Ready:** Installable as a Progressive Web App (PWA). Works fully offline thanks to Service Worker caching and lazy-loaded assets.
- **Accurate Sprite Extraction:** Implements 1:1 math matching the C++ game engine for calculating cumulative sprite offsets across massive multi-image tilesheets.
- **Lightweight:** Instead of loading 35,000 JSON game files in the browser, data is pre-compiled into minimal metadata chunks via Python.

## Repository Architecture

This repository uses a split-branch architecture to keep the static frontend fast and clean:

### `main` branch (Source Code & CI/CD)
Contains the source code, data parsing scripts, and GitHub Actions workflows.
- `ItemBrowser.html`: The complete single-file frontend (HTML/CSS/JS).
- `manifest.json` & `service-worker.js`: Required for PWA offline capabilities and mobile installation.
- `scripts/update_data.py`: The orchestrator script that runs nightly via GitHub Actions.
- `build_light_defs.py`: The Python parser that extracts entity definitions from CDDA JSON.

### `gh-pages` branch (Deployment)
This branch is automatically generated by GitHub Actions and hosts the live site.
When `update_data.py` runs, it generates a `public/` directory containing:
- The Web App frontend files (`index.html`, `manifest.json`, `service-worker.js`, etc)
- A `versions.json` manifest
- A `versions/` folder containing the processed data (`items_defs.json`, `sprite_index.json`, and optimized `gfx/` tilesets) for both Stable and Experimental releases.
The contents of `public/` are pushed to the `gh-pages` branch and served via GitHub Pages.

## How the Data Pipeline Works
Rather than forcing a browser to load and parse over 35,000 JSON game data files, this repository utilizes GitHub Actions to:
1. Automatically pull the latest Stable and Experimental Windows releases from the official CDDA repository.
2. Extract the `data/json/` and `gfx/` folders.
3. Run `build_light_defs.py` to strictly extract rendering metadata (ID, Name, Symbol, Color, Mod, Looks Like) into an `items_defs.json` (~1.5MB) file.
4. Parse the `tile_config.json` for each tileset to generate a highly optimized `sprite_index.json` containing exact sprite sheet coordinates.
5. Deploy the fast, static HTML/JS frontend that can hot-swap between game versions on the fly.

## Local Development

If you want to run this locally or test the data pipeline:

1. Clone the repository and ensure you are on the `main` branch.
2. Run the update script to download and parse the latest CDDA releases:
   ```bash
   python3 scripts/update_data.py
   ```
   *(Note: The first run downloads ~200MB of zip files. The output goes to the `public/` folder, which is gitignored on `main`.)*
3. Serve the `public/` directory via HTTP (required for `fetch()`):
   ```bash
   cd public
   python3 -m http.server 8000
   ```
4. Open `http://localhost:8000/ItemBrowser.html` in your browser.

### Fast Offline Testing
If you have a local copy of the extracted game files and want to test changes to the parsing script *without* waiting for a 200MB download from the GitHub API:
1. Create a file named `.cdda_local_path` in the repository root.
2. Paste the absolute path to your local extracted game directory (e.g., `/Users/name/.../cdda-windows-with-graphics-and-sounds-x64-...`) inside the file.
3. Run `python3 scripts/update_data.py`. The script will detect this file, skip the download completely, and instantly extract sprites from your local folder.
*(Note: `.cdda_local_path` is explicitly added to `.gitignore` so your personal directory paths will never be committed to GitHub).*
